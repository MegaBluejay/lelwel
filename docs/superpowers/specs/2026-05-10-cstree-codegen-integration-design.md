# Cstree Codegen Integration Design

## Problem

The generated parser code is tied to `CstData<Token, Rule>` where `Token` and `Rule` are separate enums. The `cstree` backend (`GreenNodeBuilder<S>`) requires a single `S: Syntax` type for both tokens and rules. Currently there is no way to use the generated parser grammar functions with the `cstree` backend — they only work with `CstData`.

## Solution

Three changes work together:

1. **`CstBuilder` trait** — token/rule types become generic type params (not associated types), `Output` becomes a GAT, `finish` takes source
2. **Codegen generates `SyntaxKind`** — a unified `#[repr(u32)]` enum combining token and rule variants, with `derive(cstree::Syntax)` + `From<Token>` / `From<Rule>`
3. **`GreenNodeBuilder` impl** — uses `Into<S>` to convert `Token→SyntaxKind` internally, zero-cost with matching discriminants

## CstBuilder Trait

Token (`T`) and rule (`R`) types move from associated types to generic parameters so `GreenNodeBuilder` can impl the trait with `T: Into<S>, R: Into<S>` bounds and handle conversion internally.

```rust
pub trait CstBuilder<T: Copy, R> {
    type Mark: Copy;
    type Checkpoint: Copy;
    type Output<'a>;

    fn new(spans: Vec<Span>) -> Self;
    fn token(&mut self, kind: T, text: &str);
    fn token_skip(&mut self, kind: T, text: &str) { self.token(kind, text); }
    fn start_rule(&mut self) -> Self::Mark;
    fn end_rule(&mut self, mark: Self::Mark, rule: R);
    fn end_rule_root(&mut self, mark: Self::Mark, rule: R) { self.end_rule(mark, rule); }
    fn mark(&self) -> Self::Mark;
    fn start_rule_before(&mut self, mark: Self::Mark) -> Self::Mark;
    fn checkpoint(&self) -> Self::Checkpoint;
    fn revert_to(&mut self, checkpoint: Self::Checkpoint);
    fn iterate_removed(&self, _checkpoint: Self::Checkpoint, _f: &mut dyn FnMut(R, NodeRef)) {}
    fn node_ref(&self, _mark: Self::Mark) -> Option<NodeRef> { None }
    fn finish<'a>(self, src: &'a str) -> Self::Output<'a>;
}
```

GAT on `Output` lets each backend choose its return type. `finish` takes the source string so backends can construct their output wrapper.

## CstData impl

No conversion needed — `T` = `Token`, `R` = `Rule`:

```rust
impl<T: TokenType, R: RuleType> CstBuilder<T, R> for CstData<T, R> {
    type Output<'a> = Cst<'a, T, R>;

    fn finish<'a>(self, src: &'a str) -> Cst<'a, T, R> {
        Cst::new(src, self)
    }
    // ... rest unchanged from current body
}
```

## GreenNodeBuilder impl

Converts `T: Into<S>` / `R: Into<S>` to `S` internally. With `#[repr(u32)]` + matching discriminants, the `into()` calls are no-ops at the assembly level.

```rust
impl<S: Syntax, T: Into<S>, R: Into<S>> CstBuilder<T, R> for GreenNodeBuilder<'static, 'static, S> {
    type Mark = Checkpoint;
    type Checkpoint = Checkpoint;
    type Output<'a> = (GreenNode, Option<NodeCache<'static, TokenInterner>>);

    fn new(_spans: Vec<Span>) -> Self { GreenNodeBuilder::new() }

    fn token(&mut self, kind: T, text: &str) {
        self.token(kind.into(), text);
    }

    fn start_rule(&mut self) -> Checkpoint { self.checkpoint() }
    fn end_rule(&mut self, mark: Checkpoint, rule: R) {
        self.start_node_at(mark, rule.into());
        self.finish_node();
    }
    fn mark(&self) -> Checkpoint { self.checkpoint() }
    fn start_rule_before(&mut self, mark: Checkpoint) -> Checkpoint { mark }
    fn checkpoint(&self) -> Checkpoint { self.checkpoint() }
    fn revert_to(&mut self, cp: Checkpoint) { self.revert_to(cp); }
    fn finish<'a>(self, _src: &'a str) -> Self::Output<'a> { self.finish() }
}
```

## SyntaxKind Enum (generated)

Generated by `gen_generated` when the `cstree` codegen feature is enabled. A single `#[repr(u32)]` enum containing all token variants (same discriminants as `Token`) followed by all rule variants (same discriminants as `Rule`, offset by token count):

```rust
#[repr(u32)]
#[derive(cstree::Syntax)]
pub enum SyntaxKind {
    // Token variants — same discriminants as Token (names unchanged)
    EOF = 0,
    Whitespace = 1,
    #[static_text("{")]
    LBrace = 2,
    // ...

    // Rule variants prefixed with "Rule" to avoid collisions with token names
    RuleError = TOKEN_COUNT,
    RuleFile = TOKEN_COUNT + 1,
    // ...
}
```

Plus generated impls:
- `From<Token> for SyntaxKind` — match-based, validated at compile time by exhaustiveness. Token variant names are unchanged.
- `From<Rule> for SyntaxKind` — match-based. Rule variants map to `RuleVariantName` in `SyntaxKind` (prefixed with `Rule`).

Compile-time assertions guarantee discriminant alignment for the optimizer:

```rust
const _: () = {
    assert!(Token::EOF as u32 == SyntaxKind::EOF as u32);
    assert!(Token::Whitespace as u32 == SyntaxKind::Whitespace as u32);
    // ...
    assert!(Rule::Error as u32 == SyntaxKind::RuleError as u32);
    assert!(Rule::File as u32 == SyntaxKind::RuleFile as u32);
    // ...
};
```

If these pass, LLVM sees identical `#[repr(u32)]` layouts and optimizes the match-based `From` to a no-op.

## LelwelBuilder + Parser

Gain `T, R` type parameters. `R` needs `PhantomData` since it only appears in method signatures, not fields.

```rust
pub struct LelwelBuilder<'s, B: CstBuilder<T, R>, T: Copy, R> {
    inner: B,
    source: &'s str,
    buffer: Vec<(T, usize, usize)>,
    start_idx: usize,
    pub in_ordered_choice: bool,
    _rule: PhantomData<R>,
}
```

```rust
pub struct Parser<'a, B: CstBuilder<T, R>, T: Copy, R, Ctx> {
    pub builder: LelwelBuilder<'a, B, T, R>,
    pub tokens: Vec<T>,
    pub pos: usize,
    pub current: T,
    pub end_of_input: T,
    pub spans: Vec<Span>,
    pub max_offset: usize,
    pub context: Ctx,
    pub(crate) error_node: Option<B::Mark>,
    pub error_since_advance: bool,
    _rule: PhantomData<R>,
}
```

## Generic Rules Trait

The generated `Rules` trait is generic over the builder, using the GAT `Output` for its return type:

```rust
pub trait Rules<'a>: ParserCallbacks<'a> + Sized {
    type Output;
    fn parse(self, diags: &mut Vec<Self::Diagnostic>) -> Self::Output;
    fn rule_file(&mut self, diags: &mut Vec<Self::Diagnostic>);
    // ... one method per grammar rule
}
```

Single blanket impl for any `B: CstBuilder<Token, Rule>`:

```rust
impl<'a, B: CstBuilder<Token, Rule>, Ctx> Rules<'a> for Parser<'a, B, Token, Rule, Ctx>
where
    Self: ParserCallbacks<'a>,
{
    type Output = B::Output<'a>;

    fn parse(self, diags: &mut Vec<Self::Diagnostic>) -> Self::Output {
        self.end_of_input = Token::EOF;
        self.parse_with(|parser, diags| parser.rule_file(diags), diags, Rule::File)
    }
    // ... generic impls for each rule method (same body, no .into() needed)
}
```

## User Code

`parser.rs` stays the same — already generic over `B`:

```rust
impl<'a, B: CstBuilder<Token, Rule>> ParserCallbacks<'a> for Parser<'a, B, Token, Rule, ()> {
    type Diagnostic = Diagnostic;
    type Context = ();
    fn create_tokens(_ctx: &mut (), src: &str, diags: &mut Vec<Diagnostic>) -> (Vec<Token>, Vec<Span>) {
        tokenize(src, diags)
    }
    fn create_diagnostic(&self, span: Span, msg: String) -> Diagnostic {
        Diagnostic::error().with_message(msg).with_label(Label::primary((), span))
    }
}
```

`lexer.rs` stays the same — still `Token` with logos, same `tokenize`.

For cstree usage (test code or opt-in):

```rust
use lelwel::cstree::*;
use lelwel_testing::CstreeDisplay;

let mut diags = vec![];
let parser: Parser<GreenNodeBuilder<SyntaxKind>, Token, Rule, ()> = Parser::new(source, &mut diags);
let (green, cache) = parser.parse(&mut diags);
let interner = cache.unwrap().into_interner().unwrap();
let root = cstree::syntax::SyntaxNode::new_root_with_resolver(green, interner);
println!("{}", CstreeDisplay::new(&root));
```

## Codegen Changes

New `cstree` feature flag on `lelwel-codegen`:

- When disabled (default): behavior identical to today
- When enabled: `gen_generated` additionally produces `SyntaxKind` enum with `derive(Syntax)`, `From<Token>`, `From<Rule>`. Also adds `#[repr(u32)]` and explicit discriminants to `Token`, `Rule`, and `SyntaxKind`.

The rule function generation is unaffected — still generates `Token::Variant` and `Rule::Variant` references. These work with any `B: CstBuilder<Token, Rule>` because the builder impl handles the conversion.

The `Parser` type references in generated code (`Parser<'a, CstData<Token, Rule>, Ctx>` etc.) update to `Parser<'a, B, Token, Rule, Ctx>` with the appropriate `B` bounds.

## File Changes Summary

| File | Change |
|------|--------|
| `lelwel/src/parser.rs` | `CstBuilder` gains `T,R` type params, GAT `Output`, `finish` takes source. `LelwelBuilder`/`Parser` gain `T,R` + `PhantomData<R>`. |
| `lelwel/src/cst.rs` | `CstBuilder` impl updates for new signature. `finish` wraps in `Cst`. |
| `lelwel/src/cstree.rs` | `CstBuilder` impl with `Into<S>` conversions for `GreenNodeBuilder`. |
| `lelwel/src/lib.rs` | Exports unchanged (re-exports parser/cstree modules). |
| `lelwel-codegen/src/backend/rust.rs` | Generic `Rules` impl, `Parser` type references, `SyntaxKind` generation when feature enabled. |
| `lelwel-testing/src/lib.rs` | No changes needed. |
